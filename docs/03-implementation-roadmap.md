# Ask-PDF Implementation Roadmap

## Roadmap rules

- No phase starts until the user approves the plan or that phase.
- Phases are sequential at exit-criterion level. Tasks marked parallel may run concurrently only after their shared dependencies are green.
- Every estimate is an initial engineering estimate in focused person-days, excluding external account provisioning/review latency.
- Every implementation task includes tests in the same focused change. A rollback means reverting that task's isolated changes; schema/index tasks also require the stated compatibility action.

## Phase exit criteria

| Phase | Exit criterion                                                                                             |
| ----- | ---------------------------------------------------------------------------------------------------------- |
| 0     | All workspaces build; local services healthy; liveness 200; worker shuts down cleanly.                     |
| 1     | Every external shape/config/error/event has one tested Zod contract.                                       |

| 3     | Auth contracts pass; refresh reuse revokes chain; CSRF/role/cross-workspace tests pass.                    |
| 4     | Browser uploads directly; API creates one queued document only after bounded verification.                 |
| 5     | Duplicate delivery/stale work harmless; durable progress survives Redis loss; SSE is authorized.           |

## Safe parallel work

- After P0: CI refinement, shared contract primitives, and local infrastructure documentation may proceed in parallel, but package versions/lockfile changes remain serialized.
- After P1: independent model groups can be implemented in parallel; tenant repository conventions must be agreed first.
- After P3: storage adapter and web upload UI skeleton may proceed in parallel against fixed contracts; completion/enqueue waits for queue contracts.
- During P6: extraction fixtures, normalization functions, and OCR detection can run in parallel after the page record contract is fixed.
- During P8/P9: vector and lexical retrievers can run in parallel; fusion waits for both. Prompt schemas and citation unit fixtures can begin against fixed evidence contracts.
- During P10/P11: frontend pages may be built in parallel by feature after each corresponding API contract is green.
- In P12: threat modeling, isolation tests, evaluation, observability, supply-chain gates, and deployment docs can run in parallel; release waits for all.
- V2 features do not run in parallel with unfinished MVP critical-path work unless the user explicitly changes scope.

## Recommended first vertical slice

After approval, implement P0-01 through P0-06 only. This produces a reproducible strict monorepo with three runnable shells, local dependencies, lint/type/build enforcement, liveness, shutdown, and CI—enough structure to make every later change reviewable without prematurely committing to business schemas or provider code.
