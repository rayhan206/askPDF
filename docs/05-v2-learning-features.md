# Ask-PDF V2 Learning and Interaction Features

## Scope rule

Nothing in this document is part of the initial MVP. “MVP+” means the first optional increment after the citation-first MVP meets its release gates and the user explicitly approves the scope. Every feature is separately feature-flagged and may be released independently.

## Shared learning-artifact architecture

All generated learning content reuses the authorized, version-aware RAG pipeline. A request snapshots `{documentId, readyProcessingVersion, pageRanges}`; source changes never silently alter an existing artifact. The API creates an artifact and enqueues an ID/version-only job on `learning.artifacts.generate.v1`. Workers reauthorize current workspace state, retrieve bounded evidence from the snapshot, generate a structured artifact, validate claims/citations, and publish progress. Redis is transient; MongoDB stores terminal artifact state and revisions.

### Shared routes and envelopes

- Every feature has a dedicated create/read route listed below.
- Common progress: `GET /api/v1/learning/artifacts/{artifactId}/progress` (authorized SSE).
- Common delete: `DELETE /api/v1/learning/artifacts/{artifactId}` -> `202` purge accepted.
- Editable features use `PATCH /api/v1/learning/artifacts/{artifactId}` with optimistic `revision`.

Common asynchronous response:

```json
{
  "data": {
    "artifact": {
      "id": "66d8a1f5213baf07a6e12000",
      "kind": "quiz",
      "status": "queued",
      "artifactVersion": 1,
      "sourceSnapshotVersion": "sha256:...",
      "createdAt": "2026-09-04T10:00:00.000Z"
    },
    "job": { "id": "learning:66d8a1f5213baf07a6e12000:1" }
  }
}
```

Common source shape:

```json
{
  "workspaceId": "66d8a1f5213baf07a6e10002",
  "sources": [
    {
      "documentId": "66d8a1f5213baf07a6e10200",
      "pageRanges": [{ "start": 1, "end": 20 }]
    }
  ],
  "clientRequestId": "018f3b2e-5c71-7d37-9ed5-d8f7b819a100"
}
```

### Shared data models

- `LearningArtifact`: `workspaceId`, `createdByUserId`, `kind`, `title`, `status`, `sourceSnapshot[]`, `sourceSnapshotVersion`, `artifactVersion`, `promptVersion`, `retrievalConfigurationVersion`, `schemaVersion`, `content`, `claimEvidence[]`, `generationUsage`, `failureCode`, timestamps, `deletedAt`, `revision`.
- `sourceSnapshot[]`: authorized `documentId`, exact `processingVersion`, optional normalized page ranges, document display-name snapshot.
- `claimEvidence[]`: stable claim/item ID, `documentId`, `chunkId`, `processingVersion`, `pageNumber`, verified excerpt, validation status/version.
- `ArtifactRevision`: immutable edited content/diff, editor, source artifact version, created time. User edits are marked as user-authored and are never represented as model-verified without revalidation.
- Queue payload: `{artifactId, artifactVersion, correlationId}` only. Evidence/text never enters BullMQ payloads.

### Shared controls and defaults

- Citation validation: identical authorization/chunk/version/page/excerpt validation as answers, plus feature-specific coverage/ambiguity rules.
- Cache: key includes environment, workspace, artifact kind, normalized options, source snapshot versions, prompt/schema/retrieval/model versions. Only validated immutable generation results cache; user edits do not populate generation cache.
- Default generation rate: 5 new artifacts/hour/user and 20/day/workspace (**proposed**); lightweight passage/page activities 20/hour/user (**proposed**). Concurrent learning jobs: 1/user, 2/workspace (**proposed**).
- Token cost: estimates below are proposed input/output envelopes. Monetary cost is computed from observed provider usage and configured current provider pricing; no static currency claim is made.
- Large files: never pass whole PDFs. Page selection and hierarchical retrieval/summarization are bounded. Multi-document generation caps source count/page ranges and requires intermediate cited section artifacts when the final context would overflow.
- Privacy: learning artifacts may reveal sensitive source content. They inherit workspace authorization, deletion, export, audit, log-redaction, and retention rules; no artifacts train/evaluate models without explicit authorization.
- Observability: every job records kind, status, duration, attempts, source/page counts, retrieved/accepted evidence counts, validation rejection reasons, model/version, input/output tokens, cache status, and estimated cost. Identifiers/content are logs, not metric labels.

## 1. Explain selected passage

| Field                             | Specification                                                                                                                                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| User problem solved               | Dense or technical text is hard to understand without losing its immediate context.                                                                                                                                                         |

| Request JSON                      | `{"workspaceId":"...","documentId":"...","processingVersion":1,"pageNumber":42,"selection":{"startOffset":120,"endOffset":480,"textHash":"sha256:..."},"audience":"beginner","detail":"concise","clientRequestId":"uuid"}`                  |
| Response/result JSON              | `{"data":{"explanation":{"id":"...","status":"ready","plainLanguage":"...","keyTerms":[{"term":"...","meaning":"...","claimId":"c1"}],"citations":[{"claimId":"c1","documentId":"...","chunkId":"...","pageNumber":42,"excerpt":"..."}]}}}` |
| Data-model additions              | `LearningArtifact(kind=passage_explanation)` plus exact selection offsets/hash and mapping version.                                                                                                                                         |
| Background job                    | Optional: synchronous within strict token/latency cap; otherwise `learning.artifacts.generate.v1`. Never block on PDF parsing.                                                                                                              |
| Prompt/artifact versioning        | `passage-explain-prompt-v1`, `passage-explanation-schema-v1`, artifact revision for saved edits.                                                                                                                                            |

| Privacy / large-file implications | Sends only selected passage + bounded adjacent evidence; never the full PDF. Selection text is not logged.                                                                                                                                  |
| Testing / observability           | Offset/hash staleness, injection, unsupported elaboration, citation coverage, accessibility; record mapping failures, tokens, latency, refusal.                                                                                             |
| Value / effort / risk / release   | High / Low / Low / **MVP+**.                                                                                                                                                                                                                |

## Cross-feature release gates

Each feature requires all of the following before release:

1. Explicit scope approval and independent feature flag.
2. Versioned request/result schemas, prompt/retrieval/artifact versions, and migration/rollback notes.
3. Tenant/source-version authorization at create, job execution, read, edit, export, and cache-hit time.
4. Feature-specific citation/ambiguity/correctness metrics meeting the approved locked evaluation set.
5. Idempotent job/session behavior, bounded token/cost/page/source limits, and actionable partial/error states.
6. Privacy/retention/deletion/export behavior and log/metric redaction review.
7. Unit, integration, cross-tenant, prompt-injection, job retry, E2E, accessibility, and representative load tests.
8. Observed token/cost/latency/failure/validation-rejection telemetry with bounded labels.
